# 🎓 Мастер-класс «Операция КИБЕРБАРЬЕР» — методичка преподавателя

Веб-стенд для студентов 1 курса специальности **10.02.05** «Обеспечение
информационной безопасности автоматизированных систем».
**Длительность: 60 минут.** Всё работает офлайн, установка не требуется.

> ⚠️ **В конце файла — ответы на все миссии. Не показывайте их студентам
> до конца занятия.**

---

## 1. Как запустить
[Стенд](https://dedomorozoff.github.io/ob-master/)
[QR код](https://dedomorozoff.github.io/ob-master/qrcode.html)

**Способ 1 (простой):** скопировать `index.html` на рабочий стол каждого ПК и
дважды щёлкнуть по файлу. Откроется браузер.

**Способ 2 (быстрый для группы):** положить `index.html` на сетевой диск и дать
студентам ссылку вида `\\server\share\index.html` — каждый открывает её у себя.

Требуется только браузер (Chrome, Edge, Firefox, Opera). Интернет **не нужен**.

Проверьте заранее:
- открывается ли файл у студента (у некоторых может быть ограничение политики);
- видно ли таймер в правом верхнем углу (должен показывать `60:00`).

## 2. Что делает студент

1. Открывает файл, читает брифинг «ты стажёр отдела ИБ», жмёт **«▶ НАЧАТЬ ОПЕРАЦИЮ»**.
2. Проходит 20 миссий в любом порядке: 1–5 — разминка, 6–10 — сложнее,
   11–20 — экспертный блок.
   За каждую миссию — **20 очков** и фрагмент кода. Максимум **400 очков**.
   Подсказка стоит **−5 очков**, ошибка **−2 очка**.
3. Собрал 10 фрагментов — получает **базовый сертификат** со своим ФИО.
   Собрал все 20 — уровень **«ЭКСПЕРТ»** в сертификате.
4. Прогресс сохраняется сам: страницу можно обновить (F5) — ничего не потеряется.

> **Если времени мало (ровно 60 минут):** базовый сертификат за миссии 1–10 —
> полноценный итог занятия. Экспертный блок 11–20 — задание на опережение
> или второй визит в кабинет: прогресс сохраняется в браузере.

Если группа прошла разминку (миссии 1–5) за 5 минут — это нормально:
стенд и рассчитан на такой темп, «сложные» миссии 6–10 съедают основное время.

## 4. Советы, чтобы час прошёл хорошо

- **Не давайте готовые ответы.** Спрашивайте: «а что не так с этим адресом?»
- **Тем, кто застрял**, скажите открыть жёлтую кнопку «💡 Подсказка» — она есть в каждой миссии.
- **Тем, кто прошёл раньше** (бывает): назначьте «куратором» — помогает соседям,
  это отрабатывает навык объяснять.
- **Рефлексия в конце** — главное: спросите каждого, какое одно правило ИБ
  он применит в своей жизни сегодня же.
- Если закончилось время, стенд **не блокируется** — таймер доходит до 00:00
  и подсвечивается красным, но работу можно продолжать.

## 5. Что студент должен вынести

| Миссия | Навык |
|---|---|
| 1. Пароль | длина важнее «сложных» замен символов |
| 2. Шифр | данные можно шифровать сдвигом; нужен ключ |
| 3. Фишинг | проверяй адрес отправителя, вложение и просьбу |
| 4. Соц. инженерия | защита — это привычка отказывать и перепроверять |
| 5. Терминал | слабый пароль подбирается мгновенно; есть базовые команды |
| 6. Два фактора | 2FA = пароль + подтверждение **другого типа** |
| 7. Права доступа | принцип минимальных прав |
| 8. Журнал | как выглядит подбор пароля в логах |
| 9. Адреса | домен читают справа налево; дефис ≠ точка; бывают буквы-двойники |
| 10. Шифр замены | подстановочный шифр и работа с ключом |
| 11. Хеш-сумма | целостность проверяют по хешу, а не «на глаз» |
| 12. Заголовки письма | SPF/DKIM/DMARC доказывают подделку; «От кого» — нет |
| 13. Аудит сервера | опасная настройка ≠ любая настройка; менять надо точечно |
| 14. Цепочка атаки | у инцидента есть хронология: письмо → выгрузка |
| 15. Крипто-инструменты | AES для объёма, RSA для ключей, хеш для целостности, ЭЦП для авторства |
| 16. Стеганография | сообщение можно спрятать в безобидном тексте (акростих) |
| 17. SQL-инъекция | единственная надёжная защита — параметризованные запросы |
| 18. Оценка риска | приоритет = вероятность × ущерб |
| 19. Wi-Fi ловушка | доверяют сети с WPA3-Enterprise и сертификатом |
| 20. Экзамен | повторение всех тем курса |
| Финал | безопасность — это процесс, а не купленный продукт; его делают люди |

## 8. Проверка стенда перед занятием (для разработчика)

В папке `tools/` лежат автотесты. Для них нужен установленный Node.js
(для самого занятия он **не нужен**).

| Команда | Что проверяет |
|---|---|
| `node tools/smoke.js` | логику миссий: шифры, пароль, фишинг, кейсы, терминал, права доступа, журнал, домены, очки, сертификат — 45 проверок |
| `node tools/check.js` | структуру `index.html`: все id, баланс тегов, отсутствие спойлеров — 60 id |
| `node tools/e2e.js` | полный проход всех 10 миссий и восстановление после F5 в headless-браузере — 56 проверок (46 + 10) |
| `node tools/qrtest.js` | QR-код на странице `qrcode.html`: независимое декодирование матриц всех версий 1–10, BCH format/version info, синдромы Рида-Соломона — 118 проверок |

Все четыре команды должны завершиться с кодом `0`. `e2e.js` сам находит Chrome
или Edge; если браузера нет — печатает `SKIP` и выходит с кодом `0`.

## 9. Если правите стенд сами

- Весь код в `index.html`: CSS в `<head>`, разметка миссий в `<body>`,
  логика — в `<script>` внизу файла.
- Текст правильного ответа миссии 2 не лежит открытым текстом: он хранится
  кодами символов (`M2CODES`), чтобы студент не подсмотрел через Ctrl+U.
- Фрагменты кода и итоговая фраза задаются массивом `FRAGS` в начале скрипта.
- Вопросы миссии 4 и пояснения миссии 3 — массивы `Q4` и `PH_EXPL`.
- После правок прогоните три команды из раздела 8.
